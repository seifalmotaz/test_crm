# UUID v7 for Primary Keys

All entity tables use UUID v7 for primary keys instead of auto-increment integers or UUID v4.

UUID v7 is time-sortable and monotonic — records created close together have lexicographically close IDs. This dramatically improves B-tree index locality in PostgreSQL compared to random UUID v4, especially for tables with heavy insertion (leads, deals, audit logs).

Unlike auto-increment integers, UUID v7 doesn't leak creation order across tenants or expose table size. It's also naturally distributed — no central sequence generator needed.

**Considered options**: Auto-increment integer (fast but leaks info, hard to shard), UUID v4 (random, poor index locality), UUID v7 (time-sortable, index-friendly, distributed).
